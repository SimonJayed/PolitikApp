# V29 Supabase rollout procedure

Approval is pending. The read-only follow-up found no `public.citation_reviews` table, and the prior implementation verified Flyway history ended at V28. V29 creates a review table and enables row-level security (RLS). It has no backfill and changes neither source records nor the WGI formula. The prior PostgreSQL 19 PGlite rehearsal ran the actual V29 SQL with representative roles. The backend integration suite exercised the Flyway profile, API authorization, publication filtering and review behavior. Supabase reported PostgreSQL 17.6 at the earlier rehearsal. Its effective grants, role inheritance and PostgREST behavior remain to be checked.

## Before running the migration

1. After approval, record the approved commit or artifact digest and the SHA-256 of `backend/src/main/resources/db/citation-migration/V29__add_citation_reviews.sql`. Use the designated Supabase direct or session-pooled connection with credentials supplied by the deployment secret store. Record the project and database identifiers separately from credentials.
2. With a read-only connection, check `current_database()`, `current_user`, `server_version`, and `to_regclass('public.citation_reviews')`. Confirm successful V28 is the last installed Flyway version, the review table is absent, and the baseline is still 970 public profiles, 53 visible published timeline entries, 44 published submissions and seven ranked profiles. Reconcile differences before proceeding. Capture row fingerprints for the four reviewable tables and the Flyway history.
3. Confirm the provider backup or PITR restore point and its retention. Make an encrypted, access-restricted PostgreSQL custom-format dump of the application schema and tables, including `public.flyway_schema_history`, `public.politicians`, `public.timeline_entries`, `public.profile_edit_submissions` and `public.politician_accomplishments`. Capture roles, relevant grants, default privileges and the deployed service configuration separately. Hash the backup, inspect its table of contents with `pg_restore --list`, and test restoration into a private PostgreSQL 17 instance. A targeted export supplements the provider backup.
4. Rehearse the approved backend artifact and configured migration on that private restore. Check existing role ownership, default grants and RLS for `anon`, `authenticated`, `service_role` and the backend database login. Direct Data API roles must have no effective access to reviews. In particular, a role with `BYPASSRLS` and table grants can see private data. Resolve any effective access before exposing reviews. The trusted backend connection must be able to perform its application queries and writes. App administrator status is enforced at the API and is independent of those database roles.

## Migrate and verify

1. Coordinate a maintenance window for automatic migrators and data writers. Use the approved backend artifact in a single controlled instance with the `supabase,citation-reviews` profiles. Keep `app.citation-reviews.enabled=false` during schema rollout, pin `spring.flyway.target=29`, use `spring.jpa.hibernate.ddl-auto=validate`, and disable scheduled news and the Open Congress importer. Use the configured Flyway runner and its normal schema history. End the one-off process after migration, validation and startup checks. Avoid ad hoc execution of the SQL or manually creating a Flyway success entry.
2. Confirm exactly one successful V29 history entry with the approved checksum, an empty review table with the expected checks and primary key, RLS enabled, zero public policies, and the expected role access. Review effective grants, including inheritance and owner status. Confirm the baseline fingerprints, withdrawals, profile count and WGI ranks still match.
3. For each running app instance that keeps Flyway validation enabled, retain both migration locations once V29 is installed. Rehearse mixed-version and restart behavior before traffic cutover. When separately cleared to enable citation reviews, enable the feature with the same locations and verify public pages and the admin queue. Expect anonymous admin requests to be rejected without authentication, ordinary citizen accounts to be forbidden, and an authorized administrator to list reviews. In the isolated environment verify authorized PUT, invalid requests, stale revisions, and resubmission after correction. Any shared PUT requires an approved record change.
4. On a representative public page, verify that pending, unverified, stale, hidden and withdrawn records do not show a verified badge. Review notes and reviewer IDs must stay private. An accessible or present imported link still displays as source-reported. Check PostgREST or the Supabase Data API separately with ordinary roles and check that any service credential is inaccessible to public clients.

## Rollback

1. Disable `app.citation-reviews.enabled`, retain both migration locations, and restart or route to an app version with compatible Flyway validation. Confirm public review responses are empty and administrator review endpoints report the feature is disabled. Leaving the additive table in place preserves any reviews.
2. If a physical reversal is separately approved, stop writers and back up the review rows, V29 history entry and current grants again. Rehearse the reversal on the private restore. In a single transaction, assert V29 is the sole latest successful entry and matches the approved script and checksum. Require a verified export and disposition for any populated table. Then drop only `public.citation_reviews` without cascade and remove only the matching V29 Flyway history row. Abort on any mismatch or dependent object. Do not restore an earlier whole-database snapshot over live application changes.
3. Verify V28 history, absence of the review table, unchanged profile and accountability fingerprints, and the original leaderboard. Return the app to the default Flyway migration locations after a physical rollback. The private schema rollback and Supabase-specific role checks are pre-rollout work. They have not been executed against shared Supabase.
