## Availability and factual verification

The HTTP check covered 68 distinct URLs, using approved-domain citations from profiles and curated records and a stable selection of imported bill URLs by Congress, chamber and host. It enforced public IPv4 resolution, default ports, approved domains and restricted query strings at each hop. It checked response headers and retried denied or unsupported HEAD requests using bounded GETs. Eight URLs returned HTTP 200 or 206, 58 returned HTTP 403, and two returned HTTP 404. These observations affected 65 distinct rows with at least one inaccessible or unconfirmed URL. The probe observed no redirects. The two 404s were biography links on PNA, and a separate retrieval supplied content for the shared historical opinion piece. Retest before treating either address as permanently broken. ## Verification workflow

The local implementation reuses the citation review queue and the existing curation and Congress publication paths. Administrators can filter citation reviews by record type, status, missing citation and record UUID. A review carries its status, source URL, source organization, notes, last review timestamp and attribution. Verified reviews require supporting evidence and a COA attribution decision where applicable. The API exposes attribution only after verification. Reviews are versioned against the underlying record. Visibility and publication remain governed by the existing workflows. Imported revisions retain their source-reported status and follow the existing Congress draft and review process.

The Supabase snapshot did not contain the citation review table. The migration is staged as V29 outside the default Flyway location. After explicit approval to deploy it, activate the `citation-reviews` Spring profile alongside `supabase` with Flyway enabled. Keep that profile active after rollout so Flyway can resolve V29. The local migration was not applied to shared Supabase. No shared records, Git commits, or remote branches were changed.
